# Redis 自定义命令实现指南

## 概述

本文档提供两种在 Redis 中实现自定义命令 `GET_OR_SET` 的方法：
- **方式一**：作为 Redis 核心命令（需修改源码）
- **方式二**：作为 Redis Module（推荐，无需修改源码）

### 命令功能

**命令:** `GET_ORدSET key default_value`

**行为:**
1. 当 key 存在时，返回 key 当前的值
2. 当 key 不存在时，将 `default_value` 设置为 key 的值，并返回新设置的值

**示例:**
```redis
> GET_OR_SET counter 0
"0"              # 键不存在，设置并返回 0

> GET_OR_SET counter 100
"0"              # 键存在，返回旧值

> INCR counter
(integer)才能够

> GET_OR_SET counter 0
"1"              # 键存在，返回当前值
```

## 实现方式对比

### 方式一：作为 Redis 核心命令

**详细文档**: [Redis 自定义核心命令实现](redis-custom-command-core.md)

**特点:**
- 需要修改 Redis 源码
- 需要重新编译 Redis
- 性能最优
- 可以使用所有内部 API

**适用场景:**
- 学习和研究 Redis 内部机制
- 需要最大性能的场景
- 对 Redis 进行深度定制

**快速上手:**
1. 创建命令实现文件 `src/t_getorset.c`
2. 在 `src/server.h` 中声明函数
3. 创建 JSON 配置文件 `src/commands/getorset.json`
4. 修改 Makefile 添加编译对象
5. 编译并测试

---

### 方式二：作为 Redis Module（推荐）

**详细文档**: [Redis 自定义模块命令实现](redis-custom-command-module.md)

**特点:**
- 无需修改 Redis 源码
- 可以动态加载/卸载
- 便于维护和分发
- 易于版本管理

**适用场景:**
- 生产环境扩展 Redis 功能
- 需要灵活部署的场景
- 第三方扩展开发

**快速上手:**
1. 创建模块文件 `src/getorset_module.c`
2. 编译为共享库 `getorset.so`
3. 加载模块：`redis-server --loadmodule ./getorset.so`
4. 测试命令

---

## 两种方式详细对比

| 特性 | 方式一：核心命令 | 方式二：Module |
|------|---------------|--------------|
| **修改源码** | 需要 | 不需要 |
| **重新编译** | 需要 | 不需要 |
| **动态加载** | 不支持 | 支持 |
| **性能** | 最优 | 轻微开销（~1-2%） |
| **API 访问** | 所有内部 API | 仅 Module API |
| **维护成本** | 高 | 低 |
| **升级难度** | 需要重新适配 | 易升级 |
| **适用场景** | 学习研究、深度定制 | 生产环境、第三方扩展 |
| **推荐度** | ⭐⭐⭐ | ⭐⭐⭐⭐⭐ |

## 选择建议

### 选择方式一（核心命令）的情况：
- ✅ 学习 Redis 内部机制
- ✅ 需要研究命令注册流程
- ✅ 追求极致性能
- ✅ 需要在命令中访问 Redis 内部数据结构

### 选择方式二（Module）的情况：
- ✅ 生产环境使用
- ✅ 需要灵活部署和更新
- ✅ 开发第三方扩展
- ✅ 希望代码独立于 Redis 源码维护

## 性能对比

### 核心命令方式
- **时间复杂度**: O(1)
- **额外开销**: 无
- **内存管理**: 直接使用内部机制

### Module 方式
- **时间复杂度**: O(1)
- **额外开销**: ~1-2%（API 转换开销）
- **内存管理**: 通过 Module API 管理

**实际性能差异**:
对于简单的字符串操作（如 `GET_OR_SET`），两种方式的性能差异通常在 1-2% 以内，在实际应用中几乎可以忽略不计。

## 常见问题

### Q1: 两种方式可以同时使用吗？
**A:** 可以。Redis 支持同时在核心命令和 Module 中注册同名命令，**Module 的命令会覆盖核心命令**。

### Q2: 核心命令和 Module 的性能差异有多大？
**A:** 对于简单的键值操作，性能差异通常在 1-2% 以内。对于复杂的批量操作，差异可能更明显。

### Q3: 如何选择合适的方式？
**A:** 优先选择 Module 方式（方式二），除非有明确的理由需要使用核心命令方式（如学习、性能优化等）。

### Q4: Module 方式安全吗？
**A:** Module 方式通过标准的 Redis Module API 工作，与核心命令一样安全。但需要确保模块代码没有内存泄漏或安全漏洞。

### Q5: 如何升级自定义命令？
**A:** 
- **核心命令**: 需要重新编译 Redis
- **Module**: 可以动态卸载旧模块并加载新模块
