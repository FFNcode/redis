# Redis 技术文档编写 Prompt 模板

## 使用说明

本模板用于指导编写 Redis 源码分析技术文档。遵循"理解概念 → 理解使用 → 深入实现"的学习路径，帮助读者循序渐进地理解 Redis 源码设计。

---

## Prompt 模板

```
请按照以下结构，分析 Redis [数据结构/命令名称] 的源码实现，生成一份完整的技术文档。

## 文档要求

### 1. 文档结构

文档应分为三个部分，符合从概念到使用的学习路径：

**第一部分：理解概念（是什么、为什么）**
- 一、概述（核心特点）
- 二、数据结构定义（结构体、类型定义）
- 三、设计特点分析（内存优化、性能优化、特殊处理）
- 四、使用场景与限制（适用场景、性能特点、转换条件）

**第二部分：理解使用（怎么用）**
- 五、操作流程图（使用 Mermaid flowchart）
- 六、示例代码理解（基本操作、内存布局）
- 七、[命令名称] 命令完整流程分析（调用流程、内存分配、robj结合使用、时序图、代码路径）

**第三部分：深入实现（如何实现）**
- 八、核心函数实现（关键函数的源码分析和解释）
- 九、源码关键点总结（内存管理、设计要点、边界情况）
- 十、测试用例分析
- 十一、总结

### 2. 内容要求

#### 2.1 数据结构定义
- 包含完整的结构体定义（引用源码行号）
- 说明每个字段的含义和用途
- 解释类型选择策略（如果有多种类型）

#### 2.2 设计特点分析
必须包含：
- **内存优化**：自适应编码、内存布局、内存效率对比
- **性能优化**：时间复杂度分析、快速路径、预分配策略
- **特殊处理**：字节序、二进制安全、边界情况等

#### 2.3 操作流程图
- 使用 Mermaid flowchart 格式
- 包含主要操作流程（创建、添加、删除、查找、扩容等）
- 标注关键判断点和操作步骤
- **注意**：节点标签中避免使用 `s[-1]` 等特殊字符，使用引号包裹或改写描述

#### 2.4 内存布局示例
- 使用 ASCII 图表展示内存布局
- 标注各字段的位置和大小
- 说明指针指向关系

#### 2.5 命令完整流程分析
必须包含：
- **调用流程**：完整的调用链（使用 Mermaid flowchart）
- **内存分配**：详细的内存分配步骤和大小计算
- **robj 结合使用**：说明 robj 和底层数据结构的关系
- **时序图**：使用 Mermaid sequenceDiagram
- **代码路径总结**：文本格式的调用树

#### 2.6 核心函数实现
- 引用源码时使用格式：```行号:行号:文件路径```
- 解释函数的功能、参数、返回值
- 说明实现原理和关键步骤
- 添加内存寻址、指针算术等详细说明（如果需要）

#### 2.7 源码关键点总结
必须包含：
- 内存管理方式
- 设计模式和技巧
- 边界情况处理
- 性能优化点

### 3. 格式要求

#### 3.1 代码引用
```markdown
```行号:行号:文件路径
// 代码内容
```
```

#### 3.2 表格
使用 Markdown 表格展示对比信息、性能特点等

#### 3.3 流程图
- 使用 Mermaid flowchart 或 sequenceDiagram
- 节点使用中文描述
- 关键判断点使用菱形节点
- 使用颜色区分不同类型的节点

#### 3.4 目录
- 使用三级标题结构
- 目录中包含章节链接
- 按学习路径分组

### 4. 编写流程

1. **先创建目录结构**
   - 确定所有章节标题
   - 建立章节之间的链接关系
   - 标注"将在后续补充"的占位符

2. **补充第一部分内容**
   - 概述和核心特点
   - 数据结构定义（需要阅读源码）
   - 设计特点分析
   - 使用场景与限制

3. **补充第二部分内容**
   - 操作流程图（需要理解源码逻辑）
   - 示例代码理解
   - 命令完整流程分析（需要追踪源码调用链）

4. **补充第三部分内容**
   - 核心函数实现（逐函数分析）
   - 源码关键点总结
   - 测试用例分析
   - 总结

### 5. 注意事项

#### 5.1 Mermaid 流程图
- 避免在节点标签中使用 `s[-1]`、`s[initlen]` 等数组访问语法
- 使用引号包裹或改写为描述性文字，如 `"设置 flags: s减1位置 = type"`
- 确保流程图语法正确，节点 ID 唯一

#### 5.2 源码引用
- 始终引用真实的源码文件路径和行号
- 如果源码有多个版本，说明版本差异
- 重要函数提供完整实现，辅助函数可以简要说明

#### 5.3 内存布局
- 使用 ASCII 图表清晰展示内存布局
- 标注地址偏移和字段大小
- 说明指针指向关系

#### 5.4 避免重复
- 同一概念在不同章节出现时，使用链接引用
- 代码示例不要重复，使用"详见 X.X 节"的方式引用
- 流程图和文字说明要互补，不要完全重复

#### 5.5 学习路径优化
- 确保读者可以按照文档顺序逐步深入
- 先建立整体概念，再深入细节
- 流程图和示例放在源码分析之前

### 6. 质量检查清单

- [ ] 目录结构完整，所有章节都有内容
- [ ] 源码引用格式正确，行号准确
- [ ] 流程图语法正确，可以正常渲染
- [ ] 内存布局图清晰易懂
- [ ] 表格数据准确，对比清晰
- [ ] 内部链接正确，可以跳转
- [ ] 没有重复内容，使用引用替代
- [ ] 章节顺序符合学习路径
- [ ] 总结部分提炼了核心要点

3. 有序性维护和二分查找
4. 内存布局和字节序处理
5. SADD 命令的完整调用流程
6. robj 和 intset 的结合使用
```

1. **结构化学习路径**：从概念到使用再到实现，循序渐进

## 使用建议

1. **先读源码**：理解数据结构设计和核心算法
2. **绘制流程图**：理清操作流程和判断逻辑
3. **追踪调用链**：从命令入口到数据结构操作的完整路径
4. **计算内存**：详细分析内存分配和布局
5. **提炼要点**：总结设计思想和优化技巧

通过遵循这个模板，可以生成高质量、易理解的 Redis 源码分析文档。
